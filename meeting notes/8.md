Meeting Summary — Aetna AI Portfolio Management (AIPM) & AI Governance Platform Integration

Meeting focus: Align Aetna’s AI Portfolio Management (AIPM) roadmap with the new enterprise AI Governance platform, define API integration requirements, establish data-sharing direction, and coordinate priorities and delivery timelines.

Overall takeaway: Both teams support integrating AIPM with the AI Governance platform to eliminate duplicate data entry, automatically initiate GenAI Governance registration, and synchronize use case information and status. The initial integration should use existing Quickbase fields as a baseline, while allowing for future intake changes and eventual enterprise universal intake.

Current status: Integration is in discovery and planning. Neither an API delivery date nor an implementation commitment was finalized.

1. Key Discussion Notes

A. Current AIPM Platform and Integration Goals

Aetna currently uses an AI Portfolio Management application developed by Productive Edge, with Andre supporting software development and enhancements.

The Aetna team has been focusing on:

* Improving the user experience.
* Making existing application functionality more robust.
* Addressing enhancements identified after rollout.
* Exploring integrations with Jira, other project management tools, and AI Governance.

Current challenge: Users enter overlapping information into multiple applications and manually maintain statuses across different systems.

Integration objective: Enable information captured once in AIPM to flow into the AI Governance platform automatically, reducing redundant registration steps and administrative workload.

B. AI Governance Platform Modernization

The Governance team is replacing legacy Quickbase-based processes with a centralized platform.

The new platform is designed to consolidate:

Platform status discussed:

D. API-First Integration Approach

The Governance team proposed exposing API functionality through the new platform, even while Quickbase remains the backend for some processes.

Proposed technical approach:

* Provide an API from the AI Governance platform.
* Initially use existing Quickbase data and backend functionality.
* Hide Quickbase implementation details behind the Governance platform’s API.
* Eventually migrate backend storage and workflows without requiring AIPM to redesign its integration.
* Use the enterprise API gateway with appropriate authentication and authorization.

Key advantage: AIPM integrates with a stable Governance API rather than directly depending on a legacy system that is being retired.

The team confirmed this approach appears technically feasible, but implementation and security details still need design review.

E. Clarification — Initial Data Flow Is AIPM to AI Governance

An important clarification occurred during the meeting.

The initial integration should primarily be a push from AIPM into AI Governance, rather than retrieving Governance data into AIPM.

The AIPM team explained that many ideas begin as early-stage concepts and never become actual implementations.

Therefore, the integration needs to determine when an AIPM idea becomes sufficiently developed to initiate a formal Governance review.

G. Two-Way Integration as a Longer-Term Goal

Although the first priority is sending information from AIPM to Governance, the team also wants eventual bidirectional synchronization.

Potential information sent back to AIPM includes:

* Governance registration status.
* Review and approval status.
* Relevant additional attributes collected during governance review.
* Production dates.
* Model registration or inventory status.

The exact endpoints, data ownership rules, and synchronization triggers were not finalized.

H. Engineering Capacity and Priority Alignment

Developing external APIs requires:

* Agreed business priority.

The team agreed to review the integration internally with the appropriate stakeholders, including Crystal, before committing to implementation timing.

6. Key Takeaways for Leadership

1. AIPM should serve as an upstream source of AI use case information. It collects business context during ideation, which can be reused when an initiative requires formal AI Governance review.

2. Use a stable API abstraction. Exposing integration through the new Governance platform can allow Quickbase migration to proceed without repeatedly changing AIPM’s implementation.

3. Start with existing field mappings. Kelly has already completed substantial analysis, so the teams can begin integration design without waiting for every revised intake question.

4. Clarify system ownership and synchronization direction. The initial flow should push AIPM data to Governance; later integration can bring review and lifecycle status back to AIPM.

5. Prioritization remains the main delivery dependency. The engineering team needs to balance this work against ongoing migration and production commitments.

6. Design for future universal intake. Although the enterprise initiative is not ready, the integration should avoid assumptions that would make later changes unnecessarily difficult.

7. Recommended Immediate Leadership Focus

For the next AIPM–AI Governance integration discussion, prioritize three deliverables:

* Field Mapping and Data Contract: Obtain Kelly’s existing mapping and Andre’s technical metadata, then identify required fields, dropdown values, and record identifiers.
* Integration Architecture: Confirm the initial AIPM-to-Governance API approach, security requirements, and whether Quickbase can remain behind the API during migration.
* Delivery and Priority Alignment: Review sprint capacity with Crystal and engineering leadership, establish an estimated implementation window, and communicate the plan to AIPM.

Overall recommendation: Start with a limited, well-defined AIPM-to-Governance intake integration, using existing metadata and a stable API. Once the foundational workflow is operational, expand into bidirectional status synchronization and future universal intake integration. This approach reduces duplicate work while avoiding unnecessary dependencies on the complete Quickbase migration.
