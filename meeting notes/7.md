Meeting Summary — AI Governance: Automated Control Review Agent, Workflow Integration & POC Planning

Meeting focus: Review Marty’s existing AI-assisted control validation process, define the target workflow in the new AI Governance platform, and align on the POC scope, engineering responsibilities, and implementation approach.

Overall takeaway: The team aligned on moving the current email-based control follow-up process into the AI Governance platform, using an AI agent to validate control implementation responses, provide immediate feedback, and reduce manual reviewer effort.

Current status: Marty has developed a working prototype using Copilot. Ragu will use the existing approach as a starting point for an integrated POC.

1. Key Discussion Notes

A. Current Challenges — Manual Control Review

After an AI use case is reviewed and approved, AI Governance assigns applicable risk controls.

The requester must explain how each control has been implemented.

A complete control response should describe:

* What is being done to satisfy the control.
* Who is responsible for performing it.
* Where / which system implements the control.
* When / how often the control is performed, if applicable.

These details are needed to support governance reviews, external audits, regulatory requests, and customer inquiries.

Current pain points:

* Responses are collected through email.
* Business owners frequently provide incomplete information.
* Marty must manually follow up and request clarification.
* Responses are recorded manually in Quickbase.
* Jira tickets are used for tracking and accountability.
* The reviewer queue can create approximately 10 days of turnaround time before users receive feedback.
* Some requesters submit their responses just before deployment.

Business objective: Provide immediate control validation, improve response quality, and reduce manual processing.

B. Existing Copilot Agent — Marty’s Prototype

Marty demonstrated an agent built using Copilot Studio, with a simplified version running through Outlook Copilot.

The agent currently performs several functions.

Capability	Description
Read control responses	Extract submitted control answers from an email thread
Evaluate completeness	Compare responses with assigned control requirements
Identify gaps	Detect missing or insufficient information
Recommend dispositions	Classify responses as acceptable or requiring further review
Generate follow-ups	Summarize outstanding questions
Support Jira tracking	Prepare standardized handoff information for tickets
Generate Quickbase output	Format assessment results for manual entry

The agent produces a standardized summary including control requirements, requester responses, evaluation results, and outstanding items.

Important limitation: The current Copilot setup cannot read from or write directly to Quickbase through the available connector, requiring manual copying.

Another important requirement is that the requester must provide the actual implementation explanation in their own words. The AI can evaluate and guide, but should not fabricate control implementation statements on the requester’s behalf.

C. Two Distinct AI Agent Responsibilities

The team clarified that two agents support different stages of the governance process.

Agent	Purpose	Primary user
Risk Assessment / Reviewer Agent	Assess the AI use case and recommend applicable risk controls	AI Governance reviewer
Control Response Validation Agent	Evaluate how the requester describes implementing those assigned controls	Business owner / requester, with reviewer oversight

Sequence: First, determine which controls apply. Then, evaluate whether the submitted implementation explanations are complete.

The existing reviewer agent can already retrieve use case information, perform risk assessment, recommend controls, and support reviewer-approved updates.

The control validation agent demonstrated by Marty addresses the next stage.

D. Proposed End-to-End Workflow

1. AI Use Case Registration

Business owner submits registration

2. Risk Assessment and Control Assignment

Reviewer agent recommends controls; Governance confirms

3. Control Implementation Responses

Requester enters an explanation for each assigned control directly in the portal

4. AI Validation

Agent evaluates completeness and identifies missing requirements

Complete

Forward result for final governance confirmation

Incomplete

Show missing information and allow requester to revise

5. Governance Review and Recordkeeping

Reviewer confirms disposition; system maintains status and audit history

Key improvement: Replace repeated email exchanges with contextual feedback directly inside the registration workflow.

E. New Portal UI Requirements

The proposed control review interface should include:

* Assigned controls displayed within the AI use case record.
* A separate response field for each assigned control.
* Ability to submit responses for AI validation.
* Immediate feedback identifying incomplete answers.
* Requester ability to revise and resubmit.
* Reviewer visibility into responses, AI findings, and final dispositions.
* Status tracking and relevant notifications.

The team preferred a structured per-control design instead of the current Quickbase approach, which stores all control follow-up details in one large text field.

This is important because different use cases can have different numbers of assigned controls, potentially including additional third-party or panel-specific controls.

F. Human-in-the-Loop Review

Although AI can evaluate completeness, the team emphasized the continuing role of human reviewers.

* AI performs the initial assessment.
* Requesters correct incomplete information.
* Governance reviewers verify important or uncertain results.
* Reviewers can override an AI recommendation.
* Final decisions should remain traceable.

The existing prototype demonstrated that the reviewer may accept an answer the agent initially flags as incomplete, such as when a valid evidence reference has already been provided.

Important distinction: A complete written response does not automatically prove that a control is operating effectively. The proposed agent primarily evaluates response completeness, with final governance judgment retained.

G. Jira and Email Integration — Future Simplification

Marty explained that Jira currently serves two main purposes:

* Tracking review volume and progress.
* Maintaining requester accountability.

The team questioned whether Jira should remain necessary once the new platform provides equivalent capabilities.

Preferred future state:

* Keep review status inside the governance portal.
* Display outstanding questions directly to requesters.
* Send email notifications when action is needed.
* Track reviewer workload and accountability within the platform.
* Reduce reliance on Jira tickets and manual emails.

No final decision was made to remove Jira.

H. POC Scope and Technical Approach

Ragu organized the meeting to clarify requirements, define Jira stories, and identify work he could begin.

The team agreed that development could proceed before the final production UI is available.

The POC should:

* Reuse Marty’s existing skills and control validation logic.
* Use the team’s approved architecture and technology stack.
* Expose validation functionality through a service or API.
* Build a lightweight demonstration UI.
* Allow users to enter control responses.
* Trigger the agent when the user clicks Submit.
* Display the agent’s validation results.

The POC should be designed for later integration into the production AI Governance portal.

Engineering direction: Build the validation service independently enough that the final UI can invoke it without requiring significant rework.

6. Key Takeaways for Leadership

1. The largest business benefit is reducing review turnaround time. Immediate AI feedback can address incomplete responses before they enter the governance review queue, potentially reducing the current roughly 10-day feedback delay.

2. Reuse the existing prototype instead of starting from scratch. Marty’s Copilot skills already demonstrate the business logic needed to evaluate control responses.

3. Separate control assignment from control validation. The existing reviewer agent identifies applicable controls. The new capability evaluates how requesters implement them.

4. Move the process into one platform. Integrating control input, validation, feedback, and reviewer decisions can eliminate much of the current email and Quickbase copying.

5. Maintain human accountability. AI should accelerate completeness checks, while requesters remain responsible for their statements and governance reviewers retain final authority.

6. Design for auditability and measurable outcomes. Control-level traceability and agent performance measurements should be incorporated as the solution evolves.

7. Recommended Immediate Leadership Focus

The most useful next deliverables are:

* End-to-end control review workflow diagram: Document the current email/Jira process and proposed portal-based process, including risk assessment, control assignment, requester response, AI validation, reviewer approval, and audit history.
* POC requirements and acceptance criteria: Confirm the inputs, evaluation outputs, reviewer override behavior, UI demonstration, and expected results for Ragu’s work.
* Production integration backlog: Identify the UI, API, workflow, notification, and reporting components required to move the POC into the new AI Governance platform.

Overall recommendation: Prioritize the validation service and lightweight POC first, while designing the longer-term experience around one integrated, traceable, human-supervised control management workflow. This will reduce manual follow-ups, improve requester experience, and establish a foundation for future AI Governance automation.
